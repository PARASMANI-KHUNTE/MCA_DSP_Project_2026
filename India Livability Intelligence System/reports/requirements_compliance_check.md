# Requirements Compliance Check

**Scope:** Checked the implementation against `India Livability Intelligence System.md` (SRS version 1.2, including the 3 November 2026 provenance update), with emphasis on M1 functional/non-functional requirements and M2–M10 deliverables.  
**Date:** 3 November 2026  
**Method:** Source and data inspection, full pytest suite, frontend production build, and frontend lint. The data pipeline, notebook sequence, local startup script, and browser interactions were not run as part of this check.

## Overall result

The application code builds and the automated tests pass, but the project's **empirical results are blocked**: six raw files exactly match hard-coded placeholder outputs formerly generated by `populate_official_data.py`. The pipeline, scoring, model, EDA, and frontend exporter now refuse those exact files; the browser bundle and derived reports are marked unverified. The current scores and research claims must not be presented as empirical results. See [data_provenance_notice.md](data_provenance_notice.md).

## Scope and data deliverable discrepancies

- SRS M0.3 now states that 32 states/UTs and 29 cities are candidate places and that the final scope is pending a source-verified coverage check. The raw recent air tables are among the blocked placeholders, so city eligibility is not yet established.
- `models/metrics.json` is stale: it says the saved K-Means run used **2018 and 42 places**, while reports describe a **2022, 61-place** cross-section. The ML runner now resolves year ties in favor of the latest broad-coverage year, but outputs cannot be regenerated until source data is replaced.
- M6.2's multiple linear regression is present in notebook 05. Assumption diagnostics (residual plots, heteroscedasticity checks, VIF) and verified outputs remain incomplete.
- The source register has empty `downloaded_on` values and licensing caveats. The boundary geometry is embedded as paths in `frontend/src/data/indiaMap.js`, with no traceable source/license entry visible in the register.
- `reports/data_quality_report.md` remains a superseded static report and contains historical claims; its warning directs readers to the provenance notice. It should not be read as current test sign-off.
- The API stats summary endpoint is a stub that says hypothesis tests will be populated after notebook 03, while findings exist separately in Markdown.

## Recommended remediation order

1. Replace the six blocked files with actual publisher records; verify their values and years, then regenerate every derived table, model, report, and frontend bundle.
2. Rerun the held-out evaluation and K-Means artifacts on verified inputs; reconcile all report values and years with the new outputs.
3. Apply the city inclusion rule to the verified air coverage table and freeze the final geography.
4. Review flagged IQR outliers and document decisions; version the final datasets.
5. Verify exact dataset licenses and map geometry provenance; keep unresolved terms visibly marked and avoid redistribution.
6. Run the pipeline twice and compare outputs, execute notebooks, then conduct browser checks for state ranking, detail/projection, comparison, 360 px layout, keyboard/color accessibility, and timing.
